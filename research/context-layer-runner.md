# Running context research cases

These papers contain adversarial examples crafted to reveal potential weaknesses in model behavior. These examples are intended exclusively for research purposes and to enhance model security and safety.

The packaged `ck research` command evaluates source-linked context recovery. It does not generate adversarial transformations or retry on refusals. The supplied eight examples are **locally authored development regressions**, not JBB, HarmBench or Behind the Mask imports and not a reproduction of the paper.

```powershell
ck research --limit 8 --output context-offline.json
ck research --live --case no-edit --limit 1 --output context-live.json
ck research --manifest external-cases.json --limit 2 --budget 4500
```

The default runs one case offline. `--limit` is bounded to 1-100 and `--case` selects one stable ID. Each selected case runs latest-only, actual retrieval and oracle conditions. Live mode explicitly sends the selected request/evidence to the configured analysis provider; it uses its existing key configuration without printing credentials. Each condition makes an interpretation call, a separate annotation-aware adjudication call, then scope and fidelity calls; bounded fidelity failures can add revision and reevaluation calls. No task provider is invoked. Choose a small limit to bound costs. Errors are recorded per condition rather than counted as success.

Offline mode indexes an isolated in-memory corpus using a documented deterministic embedding adapter and runs the actual production context builder. Its deterministic interpretation and exact-text fidelity adapters test plumbing and regressions; their decisions are **not model-quality or safety measurements**. Live mode uses the pinned local embedding implementation and configured analysis model. The candidate interpreter sees only the latest request, project and selected context; independent annotations are supplied only to the separate adjudicator. The oracle deliberately uses annotated minimum evidence to diagnose retrieval failure. It is not a retrieval measurement.

The version-1 manifest in `src/cli/context/research/cases.json` documents the record shape. `validateManifest` is the executable schema: unique IDs and source IDs, ordered prior turns, provenance/version/source case, group/split consistency, action/decision/risk enums and source references are checked before execution. External cases use the same shape. Preserve all variants of a source in one split. Only prior turns belong in `turns`; never include the latest request, future turns or annotations in indexed text. Each source ID has `harness/session#message` form. Project is session identity: do not assign one session to multiple projects. Locally supplied annotations require independent review before held-out quality claims.

Reports retain each context trace, selected IDs/excerpts, character-budget omissions, candidate interpretation/citations, gate/revisions, exact forwarded body or local block, and separate metrics with numerators and denominators. Goal and constraint semantic scores remain null offline. Task outcome/transport are unscored because this command never calls the task provider. Errors and local clarification are distinct. No composite success score exists. Single-turn versus multi-turn and variant/split labels remain in every result. The initial manifest has only multi-turn extension development examples; there is no dataset-scale quality claim or frozen target.

Structured runtime packs preserve project/session identity, chronological selected spans and bounded omission metadata. Later user turns from a retrieved session are candidates, not automatically identified corrections. They receive budget priority, but only the latest 256 later user turns per expanded session are examined. Omission details are capped at 64; total count/truncation is explicit. Search-window omissions outside 30 retrieved chunks are unknown. Character limits can still lose decisive evidence; this is reported rather than treated as correct understanding. History never verifies repository state or authorization.

For an installed HTTP integration check, import `installedProxySmoke` from the installed package's `src/cli/context/research/proxySmoke.js` using Bun. It starts a real loopback proxy with explicitly fake evaluator/provider adapters and checks zero provider calls on block/clarification, exact context audit linkage and captured completion on allow. It makes no external calls and is labelled offline. This checks installed code plumbing, not native interactive authentication or live model quality.
