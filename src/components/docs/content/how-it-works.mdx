# How it works

CheatingKit stores your local sessions in SQLite, finds the ones relevant to a new
request, and supplies cited evidence alongside that request. Nothing you typed is
changed.

## The path

1. **Import.** Claude Code and Codex JSONL, plus Hermes SQLite, become rows with source
   IDs, tool calls, models and ordering. See [Harnesses](/docs/harnesses).
2. **Index.** [MiniLM](/docs/models/minilm) and BM25 index overlapping message windows.
   The key for a window is the user's own words, so a short request is not diluted by
   surrounding assistant text. See [Local context and search](/docs/models/context-pipeline).
3. **Retrieve.** A new request is matched against that index, scoped to the current
   project. Later corrections are kept and shown as later evidence, never substituted
   for what you asked.
4. **Deliver.** A bounded [context pack](/docs/models/context-pipeline) with source IDs
   goes in through harness hooks, or through MCP.
5. **Decide.** With the proxy in the path, the [per-message gate](/docs/gate) checks the
   request before it is forwarded, and records the decision.

Hooks and the gate read the same corpus. Hooks deliver context while your harness keeps
its own provider and credentials.

## The RLM environment

A prompt can also enter an [RLM environment](/docs/repl) instead of going straight to a
provider. The request is rewritten there against your own indexed history in parallel
rounds; warnings recorded in earlier sessions are shaped by local models; and the
auditor keeps only a candidate that still outlines the original goal in neutral wording.
The winning candidate becomes the request the provider sees.

The environment is reachable through `ck repl` and through MCP, so a harness is the only
way in. Each cell runs under a capability minted for that session and budget.

## Provider relay

`ck proxy setup` configures a local loopback relay for [Codex](/docs/harnesses/codex),
[Claude Code](/docs/harnesses/claude-code) or [Hermes](/docs/harnesses/hermes). Native
credentials are preserved by default. The relay can translate between Responses,
Anthropic Messages and Chat Completions where the harness needs it. See
[Releases and installation](/docs/releases) for the routes and credential modes.

`ck proxy analysis setup` adds a separate analysis model. It is used for the gate and
the environment, never for your task provider. See [The gate](/docs/gate) for rollout
modes and decisions.
