# Local context and search

CheatingKit uses local Claude Code, Codex, and Hermes transcripts to provide source-linked context for a new request. The shared pipeline imports durable records, retrieves related user messages, attaches nearby later messages and observed warning responses, then returns a bounded context pack. The user's prompt is left intact.

## Import and index

`ck ingest` reads complete new JSONL rows or Hermes message IDs into SQLite. Source cursors and unique message IDs make repeated imports safe. `ck index` imports new rows and updates four-message search windows. Changed windows receive MiniLM embeddings; SQLite FTS5 supplies keyword matches. The index can be rebuilt from imported messages.

`ck label` separately assigns topic labels to messages and records the lead-up to observed cyber warning responses. These observations are drawn from the response text and source order. They are evidence about a prior session, not a prediction that a new prompt will receive the same response.

## Per-message recall

At a prompt boundary, CheatingKit imports new records from the current transcript or Hermes store and searches indexed history across the three harnesses. MiniLM and FTS5 contribute candidate windows. Run `ck index` to build the semantic index before using prompt context; the hook returns no context until the index is ready. Known workspace paths keep results within the current workspace; records without a workspace path can still appear. The context pack contains related user messages, nearby later user messages, nearby assistant responses, and observed warning responses. Every excerpt includes its harness, session, and message ID.

Later user messages are shown as later evidence, rather than silently replacing the earlier request. The current prompt remains authoritative. Results are limited to 4,500 characters by default; no relevant match returns no injected context.

## Harness delivery

Claude Code and Codex use `UserPromptSubmit` command hooks. Hermes uses a native `pre_llm_call` plugin. All three invoke the same `ck hook` command and database. `ck context --prompt "..."` previews that output; `ck mcp` exposes the same context builder through the `task_context` MCP tool. Install or remove the adapters with `ck hooks install` and `ck hooks remove`. Hooks deliver context while the harness keeps its own provider and credentials; they do not enforce the [per-message gate](/docs/gate).

## Gate input

When a harness uses the local proxy, the same context builder supplies evidence to the gate before a request is forwarded. The gate keeps the original request intact, evaluates the outlined task and proposed wording together, and records the retrieved source IDs with its decision. Local history is evidence for scope and authorization, not proof of either, and no provider decision is predicted from it. See [The per-message gate](/docs/gate) for the decision flow.

## Scope of the index

The corpus is indexed with MiniLM and keyword search, and topic labels come from MiniLM. Structured extraction with [GLiNER 2.5](/docs/models/gliner) supplies goal, target, and constraint fields to the gate's scope check. Observed responses are kept separate from inferred causes: the context pack reports what happened in earlier sessions without inventing a hidden goal or a numeric likelihood about a provider.
