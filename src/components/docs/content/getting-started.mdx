# Getting started

Install the published `ck` command from cheatingkit.com, then index your existing local conversations. You do not need a repository checkout or a development server.

## Install CheatingKit

First, [install Bun](https://bun.sh/docs/installation). Run the installer for your shell:

**macOS or Linux**

```sh
curl -fsSL https://cheatingkit.com/install.sh | sh
```

**Windows PowerShell**

```powershell
irm https://cheatingkit.com/install.ps1 | iex
```

The version controlled website installers look up npm's `latest` release, install that exact published version, and verify `ck --version`. For nightlies or a specific version, see [Releases and installation](/docs/releases).

## Set up local sessions

```sh
ck setup
```

Setup detects local Claude Code, Codex, and Hermes session sources. It creates `~/.cheatingkit/config.yaml` and a local SQLite database, then offers to import existing sessions, build the semantic index, and install prompt hooks. Complete the semantic index build before using prompt context. Your index remains on your machine.

Restart each harness after installing hooks. Codex may ask you to trust the hook definition. For every new prompt, CheatingKit imports new local records and supplies a bounded context pack containing related earlier user requests, nearby later user messages, observed warning responses, and exact source IDs. The current prompt stays intact.

Preview or refresh this context at any time:

```sh
ck index
ck context --prompt "Continue the loader investigation"
```

`ck hooks install` adds the prompt integrations later; `ck hooks remove` removes only CheatingKit's entries. Hooks deliver context with the harness's own provider and credentials. They do not enforce the [per-message gate](/docs/gate).

## Enable the per-message gate

The gate needs the local provider proxy; prompt hooks alone do not check a request before it is sent. Configure a separate analysis provider first:

```sh
ck proxy analysis setup
ck proxy setup codex
```

The proxy preserves the harness's native credentials by default. The analysis provider has its own key. Start the proxy in `observe` mode to record decisions without changing requests, then switch to `enforce` when the decisions are right:

```sh
ck proxy start --gate-mode observe
ck proxy attempts
ck proxy start --gate-mode enforce
```

Stop a running proxy before changing modes; `ck proxy status` reports the active mode. In `enforce`, a blocked request makes zero provider calls. See [The per-message gate](/docs/gate) for what is checked and what is recorded.

## Inspect your history

```sh
ck sessions
ck timeline
ck leadups
```

`ck sessions` lists imported sessions. `ck timeline` shows recorded events and model changes. `ck leadups` shows the messages before recorded warnings. After you have labeled messages with `ck label`, use `ck areas` for a topic summary. Run `ck index` when you want new conversations added to semantic search.

## Keep ck current

```sh
ck updates
ck update --apply
```

You can rerun the website installer to install npm's current stable release. Updates keep your local configuration and database in place. [Releases and installation](/docs/releases) explains stable, nightly, and pinned versions.
