# Releases and installation

CheatingKit publishes the `ck` CLI as the [`cheatingkit` npm package](https://www.npmjs.com/package/cheatingkit). The installers on cheatingkit.com select a published version and verify the installed command.

## Install from the website

Install [Bun](https://bun.sh/docs/installation), then run the installer for your shell:

**macOS or Linux**

```sh
curl -fsSL https://cheatingkit.com/install.sh | sh
```

**Windows PowerShell**

```powershell
irm https://cheatingkit.com/install.ps1 | iex
```

Then run `ck setup`. The website serves the installer scripts from this repository. By default, each script resolves npm's `latest` tag to an exact version, installs `cheatingkit@<version>`, and checks `ck --version`.

## Choose a release

The default `latest` tag selects a stable release. To install npm's `next` nightly instead, set `CK_TRACK` before running the installer:

**macOS or Linux**

```sh
curl -fsSL https://cheatingkit.com/install.sh | CK_TRACK=next sh
```

**Windows PowerShell**

```powershell
$env:CK_TRACK = 'next'
irm https://cheatingkit.com/install.ps1 | iex
Remove-Item Env:CK_TRACK
```

Set `CK_VERSION` to an exact published npm version to pin an installation. Available versions are listed on [npm](https://www.npmjs.com/package/cheatingkit?activeTab=versions) and [GitHub Releases](https://github.com/matthewdonsemail-lab/cheatingkit/releases). `ck --version` prints the package version, build number, and source commit.

## Update ck

```sh
ck updates
ck update --apply
```

`ck updates` checks the configured release track. `ck update --apply` installs its current published version. Use `ck update --track nightly --apply` to switch to nightlies, or `ck update --track stable --apply` to return to stable releases. You can also rerun the website installer. Updates leave `~/.cheatingkit/config.yaml` and the local database in place.

## How a version is published

The release workflow stages and checks the CLI package before npm publication. Stable releases follow the versioned release workflow and publish to npm's `latest` tag with a GitHub Release. Passing commits on `main` publish prereleases to npm's `next` tag with GitHub prereleases. The website installers read these npm tags when they run, so installation commands do not need a hardcoded version.
